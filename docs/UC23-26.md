# Customer shopping: UC-23 to UC-26

All files introduced for this work have a `Codex UC-23..26` comment.
Existing source is preserved. Integration adds only a menu in
`lib/screens/customer_home_screen.dart` and a BLL service registration in the API repository.

## Open the screens

Sign in as Customer. In the Customer app bar, open the storefront icon
(`Shopping`) and choose `Products` or `Manage my cart`.
The new screens have Products/My cart navigation. The original cart, profile,
orders and logout buttons remain available and unchanged.

- UC-23: view products, search name/brand, filter category, inspect variant prices and stock.
- UC-24: view the signed-in customer's cart and server-calculated subtotals/total in VND.
- UC-25: change quantity using +/- or the edit dialog; minimum 1, maximum current stock.
- UC-26: remove a product after confirmation; cancel leaves the cart unchanged.

Adding products to a cart and checkout are outside these four UCs. The cart
displays records already added through the project's existing cart flow.

## Backend

Additions live in the separate `EDW-For-API` repository. No migration is required.
Start it with the team's existing database/JWT configuration:

```powershell
cd D:\FPT\PRM393\Project\EDW-For-API
dotnet run --project API/API.csproj --launch-profile http
```

New endpoints all require a Customer bearer token:

| Method | Route | Purpose |
| --- | --- | --- |
| GET | /api/customer/shopping/products | Active catalog and variants |
| GET | /api/customer/shopping/cart | Current customer's cart |
| PUT | /api/customer/shopping/cart/{itemId}/quantity | JSON body: {"quantity": 2} |
| DELETE | /api/customer/shopping/cart/{itemId} | Remove owned item |

Customer identity comes from JWT, never a client-supplied customer ID.
The new endpoints do not change the existing `/api/customer/cart` endpoints.
Stock is rechecked on update; a cart does not reserve stock for checkout.

## Checks

```powershell
# Flutter repository
flutter analyze
flutter test --concurrency=1

# API repository; no database writes
dotnet build API/API.csproj
dotnet run --project tests/CustomerShopping.Checks/CustomerShopping.Checks.csproj
```

Tests cover API request identity/body, filtering, stock bounds, discounted cart
totals, cancel/confirm removal, failed mutations, disposed screens, mobile/desktop
layout, backend ownership and controller responses. Live SQL Server and real
login are not exercised by these tests.
